## 修改需求

### 需求:容器名匹配
系统必须在 PATCH 前先获取当前 workload 的容器列表，按用户指定的索引取出真实容器名，然后使用该名称构建 PATCH payload。禁止使用 `container-N` 格式的硬编码名称。

#### 场景:按索引获取容器名
- **当** 用户指定 container 索引为 1
- **那么** 系统必须先 GET 当前 workload，解析 `.spec.template.spec.containers[1].name` 获取真实容器名

#### 场景:索引超出范围
- **当** 用户指定的 container 索引大于等于容器数量
- **那么** 系统必须报错并退出，提示索引超出范围

### 需求:POSIX 兼容性
脚本必须使用 `#!/bin/bash` 作为 shebang，确保 `local` 等 bash 特性在所有环境下可用。

#### 场景:使用 bash 执行
- **当** 脚本被 Docker ENTRYPOINT 调用
- **那么** 系统必须使用 bash 解释器执行

### 需求:重试退避
系统必须在重试时使用递增等待时间，第 i 次重试等待 i 秒（1s, 2s, 3s, 4s, 5s）。

#### 场景:重试等待递增
- **当** 第一次 PATCH 请求失败
- **那么** 系统必须等待 1 秒后重试
- **当** 第二次 PATCH 请求失败
- **那么** 系统必须等待 2 秒后重试

### 需求:错误提示
系统必须在参数缺失时列出具体缺失的参数名称，而非仅提示"缺少必需参数"。

#### 场景:缺失参数提示
- **当** 用户未提供 namespace 参数
- **那么** 系统必须提示"错误: 缺少必需参数: namespace"

### 需求:超时逻辑
等待部署完成的循环必须在循环入口处统一判断超时，禁止在循环末尾存在冗余的超时检查。

#### 场景:超时判断位置
- **当** 等待部署完成
- **那么** 系统必须在每次循环开始时检查是否超时
